## 结论

LumenFocus 已有一个适合轻量 Mac 工具的底子：菜单栏常驻、默认轻提醒、本地记录、原生控件、可以随时退出休息。下一轮最有价值的工作，是让用户更少阅读、更少猜测，并在点击之前知道会发生什么。

当前主要问题不在于缺少功能或视觉装饰，而在于内部概念暴露过多、少数操作承诺与结果不一致，以及一些解释占据了主流程。应优先修复信任和可预期性，再压缩流程、补齐语言，最后精修排版。

本次使用的目标用户假设：长期在 Mac 上工作的知识工作者，希望偶尔离开屏幕，又担心提醒打断写作、设计、编程或会议。这是基于产品定位的评审假设，并非真实用户访谈结论。

## 观察方法与边界

在当前 main 构建独立体验应用 `Yvette.LumenFocus.JourneyReview`，从新偏好开始，不使用或重置正式应用数据。实际操作覆盖：四步首次引导、10 秒演示、节奏选择、跳过引导后的生效设置、手动启动 20 秒休息、等待自然结束、查看记录、四个设置页，以及选择简体中文并发起重启。

实际观察到自然完成后统计为 1 次，并在辅助功能文本中看到 `1 completed breaks`。这支持“完成记录可见”和“英语单复数有问题”两个结论。

语言重启后工具未能重新取得该菜单栏应用的窗口；因此没有把“重启后的中文全流程”写成已验证。自动到点轻提醒、暂停/延后/跳过的各分支，以界面实现和状态模型交叉审查为依据，没有伪称等待完整工作周期逐项体验。多屏、深色外观、VoiceOver 实机朗读、日法排版也不在本轮实际观察范围。透明覆盖层的窗口截图不能用于判断最终桌面合成后的明暗和对比度。

以下用“实走”表示真实操作观察，“源码”表示实现中可确定的行为，“建议”表示设计判断。未重新跑整套测试来替代体验评审。

## 视觉与交互：保留原生感，重新安排注意力

现有黑白语义色、原生开关和按钮适合这个产品。无需为了“商业化”增加渐变、大插画、卡片套卡片或主题商城。精致感更应来自稳定的层级、准确的文字、适量留白和一致的动作。

1. **首次启动聚焦一次决定。** 顶部用一句“给工作留一点离屏时间”，其后直接显示“每 40 分钟提醒 · 每次休息 5 分钟”，主按钮“开始提醒”。节奏、启动方式可改，渐暗预览为次要入口。登录启动保持可选。
2. **菜单只回答三个问题：现在是什么状态、接下来何时提醒、我能做什么。** 保留明确时间和必要的避让原因；移除长期重复的模式徽章，把工作总时长放回统计，节奏摘要可成为设置入口。保留右键原生菜单供熟练用户使用，两种入口必须共享动作语义。
3. **休息画面让视线离开。** 目前倒计时比指令更大。把远望指令作为第一层级，倒计时变安静；退出和稍后提醒仍可见、可键盘访问。不要添加需要追着屏幕看的动画、任务或健康分数。
4. **设置按用户问题分三组。** “提醒”“提醒避让”“通用”；支持、隐私、版本合入通用页尾或原生帮助入口。缩短段落，但保留在需要时能读到的准确解释。不要仅通过缩小字号来制造简洁。
5. **统计先给结果，再给细节。** 当前摘要、图表、表格重复表达同一批数据。保留一个主视图和可展开明细。零和无记录必须继续区分；精简展示不应改变数据事实。
6. **长文案适配应先于日法上线。** 原生轻提醒固定 410×196 且三个按钮横排，是法语扩展的布局风险；应按内容决定高度，必要时按钮换行或纵排。这是需要验证的风险，不是已经观察到的法语截断。

建议的首次启动信息结构：

```text
给工作留一点离屏时间
每 40 分钟提醒 · 每次休息 5 分钟       修改
到点先提醒，由你决定何时开始。

[开始提醒]
预览渐暗                   登录 Mac 时启动 □

之后可以在菜单栏调整。记录只保存在这台 Mac。
```

建议的日常菜单结构：

```text
下次提醒
14:40 · 还有 18 分钟

[现在休息 5 分钟]
稍后提醒 ▾                    暂停提醒 ▾
──────────────────────────────────────
休息记录                      设置…   退出
```

时间、时长、最近结果均来自当前状态；以上不是固定展示文案。避让和暂停时替换状态区，而不是继续堆叠新的说明块。

## 情感化设计与微文案

共情的核心是尊重用户正在做的事，让用户掌控打断，并明确操作后果。无需不断说“加油”“为了你的健康”，也不要把提前结束或跳过写成失败。避免把完成次数包装为真实离屏、专注或健康改善的证明。

下面覆盖当前可达主流程的主要措辞问题；未接入的旧字符串不应当作用户正在看到的缺陷。失败提示及系统对话框以源码审阅为主，未人为制造全部错误场景。

| 位置 | 建议中文 | 建议英文 | 用意 |
| --- | --- | --- | --- |
| 首次跳过配置（若暂时保留） | 使用默认设置开始 | Start with defaults | 不把旧值叫成刚选的“当前设置” |
| 再次运行配置时保留旧值 | 保留原设置并开始 | Keep existing settings and start | 清楚表达不提交草稿 |
| 轻提醒标题 | 离屏休息 %@ | A %@ screen break | 先说明时间成本 |
| 轻提醒说明 | 开始后，所有屏幕会渐暗。你可以随时结束。 | Starting will dim all displays. You can end the break anytime. | 就地说明后果和控制权 |
| 提前退出 | 提前结束 | End early | 区分退出与完成，不评判 |
| 跳过后的状态 | 下次提醒 %@ | Next reminder %@ | 展示结果，少讲计时器原理 |
| 完成后的菜单反馈 | 休息已完成 · 下次提醒 %@ | Break complete · Next reminder %@ | 可发现的轻量闭环，不额外打扰 |
| 提醒模式 | 提醒后手动开始／到点自动渐暗 | Remind me first / Dim automatically | 名称直接说明谁决定开始 |
| 配置间隔 | 提醒间隔 | Reminder interval | 避免“工作时长”被理解为强制工作任务 |
| 休息时长 | 休息时长 | Break length | 英文统一 break，避免 rest/break 混用 |
| 无输入规则 | 1 分钟无操作时，改用轻提醒 | Use a gentle reminder after 1 minute without input | 阈值明确，仅用于自动渐暗 |
| 避让说明 | 这些应用在前台时暂缓提醒，工作计时继续。 | Reminders wait while these apps are active. Work timing continues. | 不暗示真实会议识别 |
| 统计空态 | LumenFocus 会自动记录工作计时，完整休息也会显示在这里。 | LumenFocus records timed work automatically. Completed breaks appear here too. | 不要求不存在的“开始计时”动作 |
| 记录页尾 | 记录保存在这台 Mac，保留 90 天；可导出保存更久。 | Records stay on this Mac for 90 days. Export them to keep a longer history. | 提供有用事实，避免责任转移语气 |
| 自定义方案 | 自己设定 | Set your own | 替换 Roll your own，照顾非英语母语用户 |
| 演示进行中 | 演示中… | Demo in progress… | 替换 Demoing… |
| 登录启动 | 登录 Mac 时启动 | Launch at login | 区分登录与开机 |
| 登录启动失败 | 未能更改登录启动设置。请在系统设置的登录项中检查。 | Couldn’t change launch at login. Check Login Items in System Settings. | 给出可执行的恢复方法 |
| 重启失败标题 | 未能重新启动 | Couldn’t relaunch | 不复用不准确的“系统设置”错误标题 |
| 暂停状态 | 已暂停至 %@ | Paused until %@ | 英语用状态而不是祈使指令 |
| 跨午夜的时间 | 明天 %@ | Tomorrow %@ | 避免只显示 00:30 让用户猜日期 |

 `%@` 应插入完整的本地化时长/时间；句子按语言独立翻译，不通过碎片拼接。到点时左键面板、右键菜单和辅助功能标签应采用相同动作名。

“提前结束不计入完成次数”可以放在帮助或记录说明中；不要用红字、确认弹窗或倒计时威胁用户留下。健康边界、数据保留规则仍需准确，只是不必在每个界面的第一行重复。

## 多语言架构：有基础，但还不是四语言产品

| 用户关心的问题 | 当前事实 |
| --- | --- |
| 是否默认英语？ | 不是强制英语。`AppSettings` 默认 `.system`；开发语言为 `en`。当前设备得到英语，不代表所有新用户都默认英语 |
| 能否切换中英文？ | 有应用内选择器，选项是跟随系统、简体中文、English；通过写入 `AppleLanguages`，重启生效 |
| 是否支持日文、法文？ | 尚未支持：没有语言枚举项和相应翻译资源，也没有完成对应排版体验 |
| 是否完全硬编码？ | 不是。已有 `NSLocalizedString` 封装和两套 `.strings`；SwiftUI 字面量很多也会自动作为本地化键。不能看到中文源码就判定没有国际化 |
| 是否已经完整？ | 尚未。缺少复数资源，实际出现 `1 completed breaks`；没有统一说明应用语言与地区格式的关系；异常详情可能来自系统语言 |

证据：[AppSettings.swift:6](../LumenFocus/LumenFocus/Models/AppSettings.swift#L6)、[默认值:127](../LumenFocus/LumenFocus/Models/AppSettings.swift#L127)、[语言持久化:135](../LumenFocus/LumenFocus/Models/AppSettings.swift#L135)、[语言设置:216](../LumenFocus/LumenFocus/Views/SettingsView.swift#L216)。SwiftUI 字面量的行为参见 Apple 的 [LocalizedStringKey 文档](https://developer.apple.com/documentation/swiftui/localizedstringkey)；系统语言匹配参见 [Bundle preferredLocalizations](https://developer.apple.com/documentation/foundation/bundle/1409418-preferredlocalizations)。

建议保留“跟随系统”为首次默认，英语作为开发和回退语言。如果产品策略明确要求所有新用户先看到英语，再单独变更默认策略；这与“支持英语”是不同决定。

最小可持续扩展方案：

1. 增加 `ja`、`fr` 枚举、项目语言声明、资源和校验清单；选择器用原生名称 `日本語`、`Français`。
2. 使用 String Catalog 或 `.stringsdict` 处理单复数；选择一种资源策略，避免长期维护重复资源。翻译范围包括 AppKit 面板、菜单、辅助功能、错误和空态。
3. 把时长、相对日期、跨日提醒的显示格式集中管理。界面语言与地区习惯分别处理，尊重用户时区和 12/24 小时设置。CSV 字段及持久化日期格式是数据协议，不需要跟着界面翻译。
4. 记录当前已应用语言和待应用语言，仅有变化时提示重启；应用后恢复到语言设置页，减少“应用消失了”的疑惑。首发可以保留重启，不必优先开发全应用即时换语。
5. 英、中、日、法各走一遍从启动到休息结束的真实流程，尤其看法语长按钮、日本语换行、单复数和原生窗口标题。只检查翻译键一一对应不能证明体验完整。

## 硬编码与组件化

已经具备的良好结构：`CycleEngine` 统一行为、`ReminderPresentation` 统一状态和时间显示、`StatisticsPresentation` 统一记录范围；界面使用原生 `Form`、`TabView`、`Button`，有共享语义色。这不是需要全部推倒重写的 UI。

仍值得整理的地方：

| 类型 | 现状 | 合理改法 |
| --- | --- | --- |
| 动作和时长策略 | 延后 2/5/10、暂停 15/60、默认延后 120/300 秒散落在原生菜单、SwiftUI 菜单、提醒和覆盖层 | 一个小型动作描述/策略层统一标签、目标时间和行为参数；各入口继续使用适合自己的原生控件 |
| 共享时长选择 | `restDurationChoices`、`restDurationText` 定义在 OnboardingView 文件末尾，其他页面也依赖 | 移入独立的时长呈现文件，必要时复用一个轻量 `BreakDurationPicker` |
| 规则名单 | 会议、演示、媒体应用 Bundle ID 写在 WorkspaceMonitor，界面只显示类别 | 集中规则定义并用于展示名单。固定名单可接受，隐藏名单导致的不可预期才是问题 |
| 布局约束 | 菜单 350 宽、提醒 410×196、统计列宽等局部常量 | 保留合理最小宽度；会被翻译撑开的地方改内容自适应。不要把每个 padding 都配置化 |
| 颜色与视觉样式 | 语义色可用，同时保留多套灰阶和重复别名 | 删除无调用项，留下背景、主次文字、边界、主操作等少量语义；不建设庞大 Design System |
| 未接入功能 | 呼吸/移动圆点、无资源音频、未集成 Widget、未用数据模型等旧骨架 | 经引用确认后清理，或明确移出首发路径；不要因为有代码骨架就把功能塞给用户 |
| 地址与数据格式 | 隐私 URL、支持邮箱已集中；CSV/持久化键固定 | 这些常量合理。除非存在真实运营需求，不引入远程配置或后台 |

优先复用的是**相同意义和行为**，其次才是外观。一个共享按钮外观不能避免两个入口的“稍后提醒”使用不同默认时长；统一动作模型更有价值。

## 奥卡姆剃刀：做减法的边界

- 删除独立演示步骤、日常菜单的重复模式标签、统计主摘要中的活动日指标，以及未使用的代码骨架。
- 合并重复说明，把数据口径、隐私和支持放入能找到的次级位置；折叠逐日表格。
- 保留延后和暂停的语义区别、全程可退出、明确下一次时间、零与无记录的区别，以及可选的自动渐暗。
- 不引入首页仪表盘、账号、云同步、打卡奖励、健康评分、社交比较、复杂自动化规则或大规模自研组件框架。

极限版本的核心承诺只有一句：**在合适的时候提醒我离开屏幕，并始终让我决定现在是否方便。** 每个首发功能都应能解释它怎样服务这句话。

## 建议实施顺序与体验验收

### 第一批：让操作可信、后果可预期

修复引导提交冲突；统一提前结束/完成用词；提醒显示休息长度和渐暗后果；统一默认延后策略并显示目标时间；说明前台应用规则；修复英语复数。

验收不以测试数量衡量：新用户所选节奏确实生效；开始前知道会休息多久；延后、跳过、提前结束后能说出下次何时提醒；知道为什么暂时没收到提醒。

### 第二批：简化主流程，同时建立四语言基础

一页开始、紧凑菜单、三组设置、简洁统计；集中动作/时间格式与可复用时长控件；接入日法资源、复数和待应用语言状态。同步清理确定无用的骨架，避免边改边扩大产品范围。

验收：默认路径不要求阅读四页说明；主要动作无需理解“引擎、口径、阶段”等内部概念；切换语言后主流程、菜单、原生面板和辅助功能文案一致。

### 第三批：视觉与情感细节

调整休息页主次层级、间距和按钮布局；加入菜单中的轻量结果反馈；检查长文案、小窗口、键盘和辅助功能阅读顺序。保留原生界面风格。

邀请少量符合目标画像的首次使用者完成同一组任务，记录他们在哪里停顿、猜测或理解错误；不要只问“好不好看”。以上建议是专家评审，真实使用反馈用于验证和修正取舍。

涉及计时、暂停和记录语义的修改仍应有针对性的回归验证；纯文案与排版主要用实际任务走查确认。已有 App Store 准备工作继续保留，开发者账号、签名和商店提交仍待账号准备完成。
